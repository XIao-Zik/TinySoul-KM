## 背景

本机部署 TinySoul（后端项目 `D:\ProgramData\RESUME\my-agent`，GLM-4.5-Flash 免费 provider）过程中发现两个使用问题：

1. **项目路径硬编码**：`visualization/src/store/appStore.ts` 中 `projectRoot` 默认值写死为前端作者本机路径 `"B:/WorkSpace/TinySoul-Agent"`。任何其他部署者启动桌面端后，自动发现（Tauri `discover_backend` → 按 project root 哈希读 `%LOCALAPPDATA%\TinySoul\instances\<identity>.json` 实例租约）必然失败，只能停在手动连接页。代码中已预留 `setProjectRoot` action，但没有任何 UI 消费它，属于未接线状态。
2. **启动链路繁琐**：日常使用需要"先起后端、再 `pnpm tauri dev` 起前端"两条命令、两个终端窗口。`pnpm tauri dev` 是开发模式（vite + cargo watch 常驻），启动慢、占资源，不适合作为日常入口。

临时处理记录（已生效，但按本方案将被替换）：

- `appStore.ts:73` 当前被临时改为 `"D:/ProgramData/RESUME/my-agent"`（本机专用硬编码，方案执行时应改回空默认值）。
- 应用 WebView2 缓存（`%LOCALAPPDATA%\com.tinysoul.visualization\EBWebView`）已清除一次，以让新默认值生效；注意 persist 的 localStorage 旧值优先于代码默认值，改默认值后必须清一次缓存。

## 方案一：项目路径软配置（前端两处小改）

### 改动 1 · ConnectScreen 增加 Project root 输入框（核心）

- 位置：`visualization/src/components/shell/ConnectScreen.tsx`，在 Address 输入框上方。
- 行为：输入框双向绑定 `useAppStore` 的 `projectRoot` / `setProjectRoot`（store 已有 persist，自动持久化到 `tinysoul-ui-state`）。
- 交互：`projectRoot` 为空时，"Use the local instance of this project" 按钮置灰并提示先填写路径；启动自动连接（`connection.ts` 的 `autoConnect(projectRoot)`）为空时跳过 discovery，不报错。
- 说明文案：解释"本地实例发现按此路径计算项目身份哈希，填 TinySoul 项目根目录（含 tinysoul.toml）"。

### 改动 2 · 撤掉硬编码默认值

- `appStore.ts:73` 默认值改为空字符串 `""`，不指向任何人的机器路径。
- 部署者首次使用时在连接页填一次自己的项目根目录，persist 永久记住。

### 改动 3（可选，暂不执行）· Rust 侧智能发现

- `visualization/src-tauri/src/lib.rs` 的 `discover_backend` 旁增加 `list_backends` 命令：扫描 instances 目录下全部合法租约；`projectRoot` 为空时，仅一台实例则直连，多台返回列表由前端出选择 UI。
- 优点是零配置；缺点是改动面扩大到 Rust 侧并偏离上游"按项目根发现"的设计意图。
- **决定：第一版不执行**，改动 1+2 已完整解决问题。

## 方案二：正式版构建 + 一键启动 + 桌面快捷方式

### 步骤 1 · 一次性正式构建（约 15~25 分钟）

- 命令：`pnpm tauri build`（`tauri.conf.json` 已配置 `targets: "all"`、官方 icon.ico）。
- 产物：NSIS 安装包 + 独立 `TinySoul.exe`（`visualization/src-tauri/target/release/` 与 `target/release/bundle/`），产物约 2~3 GB，落在 D 盘。
- 效果：日常启动不再依赖 pnpm / vite / Node / 源码目录；与开发模式（`pnpm tauri dev`）并存互不影响。

### 步骤 2 · 一键启动脚本 `D:\ProgramData\RESUME\start-tinysoul.ps1`

- 逻辑：读实例租约并探测 `/v2/health` → 后端未运行则静默启动 `tinysoul start --root <项目>` 并等待就绪（带超时）→ 再启动正式版前端 exe。
- 幂等：重复执行不会起第二个后端；后端意外退出时再次双击可自动拉起。
- 环境注意：脚本内需自带 `CARGO_HOME`/`RUSTUP_HOME`（现为 `D:\Program Files (x86)\rust\*`）与 conda env python PATH，不依赖用户终端的 PATH 状态。

### 步骤 3 · 桌面快捷方式

- 名称 "TinySoul"，指向 `start-tinysoul.ps1`（或其 exe 包装），图标取 TinySoul 的 ico。

### 可选 · 开机自动启动后端（待定）

- 计划任务/启动项静默拉起后端；做了之后每天只需双击前端。默认不做，待确认。
